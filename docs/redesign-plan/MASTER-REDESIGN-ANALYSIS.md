# GeoSR 홈페이지 전면 재설계 분석 기준

작성일 2026-09-18
상태 다음주 디자인 착수 준비 완료

이 문서는 사용자가 전달한 전면 재설계 마스터 지시서를 다음 작업에서 바로 실행할 수 있도록 정리한 운영 기준이다

## 기준 우선순위

1. 사용자의 최신 직접 지시
2. 전면 재설계 마스터 지시서
3. 저장소에서 확인된 실제 자료와 출처
4. 기존 설계 문서의 참고 아이디어
5. 현재 구현과 과거 목업

과거 레이아웃, 카피, 영상 길이, CSS, 페이지 순서는 보존 의무가 아니다
실제 회사 정보, 장비, 연구, 플랫폼 화면, 원본 출처와 과학적 사실성은 보존한다

## 재설계의 핵심 결론

GeoSR은 자연 풍경을 보여주는 회사가 아니라 현장에서 데이터를 얻고 과학적으로 분석하며 모델과 AI로 해석하고 플랫폼으로 전달하는 해양·환경 기술기업으로 보여야 한다

핵심 흐름은 다음과 같다

`OBSERVE → ANALYZE → MODEL → PREDICT → DELIVER`

최종 인상은 다음 질문에 답해야 한다

- 현장 관측과 장비 역량이 보이는가
- 분석과 모델링과 AI가 실제 업무 흐름으로 연결되는가
- AX Platform과 GeoDAP이 실제 서비스로 이해되는가
- 생성 콘셉트와 검증된 자료가 구분되는가
- 국내 기업의 신뢰성과 국제 기술기업 수준의 화면 완성도가 함께 있는가

## 정보 구조

상위 진입은 다음 8개 흐름으로 설계한다

1. Home
2. Business / Technology
3. Research / Results
4. Platform
5. Observation / Equipment
6. Company
7. News
8. Contact

Home은 목록이 아니라 다음 서사로 연결한다

1. Hero Film
2. Field / Observation
3. From Data to Understanding
4. Technology / Capability
5. AX Platform
6. GeoDAP
7. Evidence
8. Company / Contact

기존 21개 기술 상세와 게시판과 검색·필터 개념은 데이터 차원에서 보존한다
첫 화면에는 21개 항목을 모두 나열하지 않고 상위 기술 흐름으로 안내한다

AX Platform은 회사 홈페이지 안에서 소개하는 별도 제품 경험이다
GeoDAP은 `Earth Data Intelligence Platform`이라는 독립 서비스로 소개하고 외부 사이트로 연결한다
두 서비스를 하나의 하위 기능이나 통합 제품처럼 표현하지 않는다

## 시각·콘텐츠 원칙

현실적인 기술기업, 영화적인 연출, 과학적 신뢰를 동시에 유지한다

사용하지 않을 표현

- 파란 네온 회로와 무의미한 격자
- 장식용 입자와 HUD
- 가짜 지도, 가짜 수치, 가짜 범례, 허구의 실시간 결과
- 사이버펑크와 미래도시와 과장된 장비
- 모든 내용을 동일 카드에 넣는 SaaS식 구성
- 자연 풍경만으로 기술을 대신하는 화면

색은 GeoSR의 기존 푸른 계열과 검정과 어두운 남색을 중심으로 하되 전체를 청색으로 덮지 않는다
실제 데이터의 범례색은 원자료 의미를 유지할 때만 사용한다
대형 타이포그래피는 개념을 강조하는 곳에만 쓰고 한글 문장은 자연스럽게 다시 작성한다

## 자산 출처 체계

모든 이미지, 영상, 캡처, 문서, 생성 결과는 다음 중 하나로 표시한다

- `VERIFIED SOURCE`
- `VERIFIED OUTPUT`
- `EDITED SOURCE`
- `CONCEPT`
- `GENERATED CONCEPT`
- `PLACEHOLDER`

각 자산에는 최소한 다음 메타데이터를 붙인다

- 원본 경로 또는 URL
- 촬영·수집·제작 상태
- 사용 페이지와 장면
- 사실 검수 상태
- 생성·편집 금지 요소

사람이 없는 장비·지형·센서 중심 이미지를 기본으로 한다
사람이 포함된 실제 현장 원본은 사실성과 권리 검토 후 예외적으로 사용한다
생성 이미지에 새 장비를 임의로 만들지 않고 실제 GeoSR 장비 원본을 기준으로 한다

## 영상 방향

메인 기업 영상은 데이터가 어디서 오는지를 보여준다
지구와 위성 원격탐사에서 한반도와 인근 해역, 연안과 항만과 하천, 조사선과 무인선, 드론과 LiDAR, 부이와 수중 센서와 ROV, 실험 분석, 수치모델, AI와 플랫폼으로 이어지는 10개 장면을 검토한다

AX 영상은 메인 기업 영상과 분리한다
현장 장비를 반복하는 대신 `REAL COAST → DETECT → PREDICT → MONITOR → ACTUAL AX SCREEN`으로 제품 판단 경험을 보여준다
AX 아래의 플랫폼별 영역은 실제 16:9 화면 녹화나 GIF와 MP4를 사용한다

이 문서 작성 당시 Hero와 기업 소개 영상의 길이는 고정하지 않았고, Hero Loop 15~30초와 Corporate Film 45~75초 후보 범위를 기록했다. 이 과거 후보 범위는 2026-09-20 최신 확정으로 대체되었다.

### 2026-09-20 확정

현재 제작 기준은 회사 메인 필름 약 60초와 AX 콘셉트 인트로 약 30초다. 이 확정 길이가 본 문서의 이전 후보 범위와 과거 프리비주얼 기록보다 우선한다. 최신 manifest revision `preproduction-20260919-r2`에서 `geosr-hero`는 60초, `ax-concept-film`은 30초이며 나머지 슬롯 길이는 유지한다.

제작 순서

1. 실제 원본과 장비 근거 확보
2. 장면별 시작·중간·끝 프레임 제작
3. 지리·장비·과학 사실 검수
4. 저해상도 Flow 모션 테스트
5. 승인된 장면만 Higgsfield 고해상도 제작
6. 데이터 그래픽과 실제 UI는 후반 합성
7. 웹용 인코딩과 poster·reduced-motion·모바일 버전 제작

## 디자인 보드와 구현 게이트

코드를 먼저 수정하지 않는다
다음 3개 방향을 실제 자산으로 구성해 비교한다

### Direction A — Cinematic Scientific

전체 화면 영상과 큰 공간 전환을 중심으로 기술 여정을 보여준다

### Direction B — Spatial Editorial

대형 실사 이미지와 공간정보 레이어와 편집 디자인을 결합한다

### Direction C — Interactive Technical

스크롤 기반 관측 → 분석 → 모델 → 예측 흐름과 실제 플랫폼 화면을 중심으로 한다

세 방향은 색상만 바꾸지 않고 Hero, Field, Technology Story, Numerical / AI, AX, GeoDAP, Evidence, Contact의 레이아웃과 화면 리듬을 다르게 만든다
각 방향에는 데스크톱 1440~1920 기준 보드와 모바일 적응안을 함께 둔다

사용자가 한 방향을 선택하기 전에는 전체 HTML·CSS·JS 구조를 전면 교체하지 않는다
Hero 영상을 먼저 생성하지 않는다

## 인터랙션·성능·접근성 기준

GSAP과 ScrollTrigger와 Lenis와 CSS mask와 clip-path를 기본 후보로 둔다
Three.js와 WebGL과 GLSL은 지구, 위성 관측 범위, 수층, 지형, 데이터 레이어처럼 의미가 있는 장면에만 사용한다
가장 단순한 구현으로 목적을 달성할 수 있으면 WebGL을 사용하지 않는다

필수 검수

- poster-first와 lazy loading
- 화면 밖 영상 일시정지
- 모바일 전용 crop 또는 edit
- `prefers-reduced-motion`과 save-data 대응
- 키보드 focus와 semantic link·button
- 영상 재생·정지 조작
- alt와 명도 대비
- dialog Escape와 언어 상태 유지
- 콘솔 오류와 404와 빌드 검증
