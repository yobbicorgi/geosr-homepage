# 페이지 디자인 — GeoSR의 기술을 읽히게 만드는 화면

메인 설계 · 2026-09-17 · 목업 제작 기준

## 1. 디자인의 중심

**넓은 현장 영상에서 시작해, 실제 기술 결과와 명확한 한국어 정보로 이어지는 국내 기술기업 홈페이지.** 첫 화면은 몰입을, 이후 화면은 이해와 탐색을 담당한다. 풍경 영상만 계속 보여주거나 영어 문구·추상 도형만으로 기술기업처럼 꾸미지 않는다.

올포랜드의 실사와 공간 그래픽, BNT의 데이터 결과를 크게 보여주는 방식을 참고한다. GeoSR은 관측·환경·생태·모델·AI·공간정보의 폭을 자체 자료로 드러낸다. ‘경쟁사보다 우수’는 아직 달성한 결과가 아니라 가독성·기술 이해·자료 접근·모바일 품질로 검증할 목표다.

## 2. 기본 화면 언어

| 항목 | 결정 |
|---|---|
| 색 | 심해색 `#102A38`, 본문 `#172D3A`, 밝은 면 `#F7F8F6`, 흰색 `#FFFFFF`, 주 강조 `#006D77`, 보조 그래픽 `#56C5D0` |
| 신호색 | 재해·위험 결과에만 `#BD5637`. 과학 결과의 범례는 원자료 기준을 유지한다 |
| 글꼴 | Pretendard 우선, 없으면 Noto Sans KR·시스템 한글. 영어도 같은 계열. 폰트 로딩 실패에도 내용과 폭 유지 |
| 글자 | 데스크톱 H1 64/76, H2 40/52, 본문 18/30, 보조 14/22px. 모바일 H1 36/46, H2 28/38, 본문 16/27px |
| 배치 | 1440 화면에서 내용 폭 1280, 양옆 80. 12열/간격24. 모바일 390에서 양옆20, 4열/간격16 |
| 여백 | 섹션 상하 112px, 모바일64px. 내용은 16·24·32·48 단위로 묶는다 |
| 형태 | 큰 미디어는 직각 또는 4px. 버튼6px. 필터만 pill. 모든 영역을 둥근 카드로 감싸지 않는다 |
| 이미지 | 실제 관측·장비·모델 결과를 충분히 크게. 장식용 그래프·가짜 수치·무의미한 격자를 넣지 않는다 |

11px 수준의 기술 라벨을 핵심 정보에 쓰지 않는다. 필수 범례·시간·단위는 모바일에서도 13px 이상, 설명 본문은16px 이상으로 읽히게 한다. 강조색 대비는 구현 단계에 실제 조합으로 검사한다.

## 3. 메뉴와 탐색

순서는 **사업·기술 → 연구·성과 → 플랫폼 → 관측·장비 → 회사소개 → 소식**, 우측에 문의와 KR/EN. 데스크톱 헤더80px, 모바일64px. 전체 메뉴가 맞지 않는 폭에서는 글자를 줄이지 않고 동일한 접힘 메뉴로 전환한다. 기본 전환점은1280px이며 영어 최장 메뉴를 기준으로 확인한다.

사업·기술의 넓은 메뉴는 두 관점을 제공한다.

- 업무별: 수환경 보전 / 수환경 건강성 회복 / 재해예방 / 스마트 기술. 기존 공식 21개 상세의 제목·ID를 보존한다.
- 기술별: 관측·측량 / 환경·생태 / 수치모델·예측 / 위성·영상 / AI·데이터 / 공간정보. 원문을 찾기 위한 교차 분류이며 새로운 사업 실적을 뜻하지 않는다.
- USV와 전자해도는 바로가기. 플랫폼은 AX 소개와 GeoDAP를 구분한다.

메뉴는 클릭·키보드·터치로 동일하게 열리고, 모바일에서는 큰 아코디언이다. 검색은 자료 찾기 기능이며 첫 화면에서 팝업으로 방문을 방해하지 않는다.

## 4. 홈 — 일곱 구간의 화면 구성

### A. 첫 화면: 기술이 보이는 현장

**사용자 확정: 첫 진입에서 전체 화면에 영상이 바로 재생된다.** 데스크톱·모바일 모두 첫 섹션을 폭100%·높이100svh로 만든다. 높이860px 같은 상한을 두지 않는다. 브라우저 전체화면 API를 강제로 실행한다는 의미가 아니라 현재 뷰포트를 채우는 것이다. 영상은 `cover`로 채우고 헤더는 그 위에 겹친다. 데스크톱은 좌측 아래5열을 문구 안전 영역으로 남긴다. 영상의 실제 결과는 우측·상단에 배치해 글과 경쟁하지 않게 한다. 단색 흰 카드가 아니라 영상 위 제한된 어두운 그라데이션으로 대비를 만든다.

**국문:** 현장을 관측하고, / 변화를 예측합니다.  
**영문:** Observe the environment. / Anticipate change.

보조: ‘현장 조사부터 수치모델·AI 분석까지, 해양과 수환경의 변화를 이해하는 기술.’  
영문: ‘From field surveys to numerical models and AI, we help make sense of changing oceans and aquatic environments.’

주 버튼 ‘사업·기술 살펴보기 / Explore our technologies’, 보조 ‘연구·성과 보기 / Explore our research’. 우측 아래 영상 재생·정지, 현재 장면명. 실제 목업에서는 `[목업 영상 영역]`을 분명히 표시한다. 기업 소개 원본 영상은 별도 보기 버튼으로 연다.

모바일도 **첫 화면 전체가 영상**이다. 가로본을 무심하게 잘라 쓰지 않고9:16에 가까운 별도 구도·피사체 중심점을 지정한다. 제목은 하단 안전 영역에2줄, 주 버튼1개와 재생/정지를 최소 배치한다. 상세 보조설명·보조 버튼은 첫 스크롤 이후 밝은 섹션으로 보낸다. 로고·메뉴·제목·기술 결과가 겹치지 않는 구도를 확보하고 safe-area inset을 반영한다. 영상이 세로구도에 맞지 않으면 목업에서는 빈 전체화면 영상 슬롯을 쓰며, 작게 들어간 가로영상으로 대체하지 않는다.

### B. 전문 분야: 큰 화면 하나와 분명한 목록

밝은 면. 왼쪽에 ‘다양한 환경, 하나로 연결되는 전문성’, 오른쪽에 공식4개 업무명을 큰 행으로 배치한다. 선택한 행에는 대표 기술2개와 설명1줄, 관련 이미지1장이 나타난다. 카드4개를 같은 크기로 늘어놓지 않는다. 모바일은 아코디언으로 열린 영역 하나만 유지한다.

### C. 기술의 과정: 관측에서 판단까지

어두운 미디어 판1개와 밝은 설명 열. 관측 자료→지형·모델→예측 결과→적용 문제의4단계. 실사에 그래픽 선을 얹는 연출이 아니라 실제 입력과 산출물의 차이를 보여준다. **서로 다른 사업의 자료를 한 자동 시스템의 출력처럼 이어 붙이지 않는다.** 대표 사례를 확보하기 전에는 단계별 목업 도형과 예시 표시를 쓴다. 정확한 동작은02번 문서.

### D. 대표 기술: 결과가 주인공인 편집 구성

큰 대표 항목1개(화면 폭의2/3)와 보조 항목2개. 목업은 ‘수환경 통합모델링 / 무인선 이용 관측 / 인공지능 활용기술’을 사용한다. 주인공 결과의 이미지·짧은 목적·관련 기술·상세 버튼이 한 덩어리가 된다. 기술 전체 목록은 별도 허브에서 찾는다.

### E. 연구·성과: 읽을 수 있는 실적

사업 / 연구 / 학술 탭과 대표 글3행. 제목·연도·기관/저자·분야만 보여주고, 실제자료1건과 명시된 예시행으로 형식을 검증한다. 전체 수집 건수를 현재 목업 검색 결과처럼 표시하지 않는다. ‘전체 자료실’은 목업 목록으로 연결한다.

### F. 플랫폼과 현장 역량

플랫폼 캡처 큰 화면1개, 우측에 입력·기능·결과3행. 그 아래 조사·실험·선박의 현장 자산을 가로 스트립으로 배치한다. 목업에서는 플랫폼2개와 장비3개만 쓴다. 현재 서비스 상태는 캡처 이미지와 별개이며 ‘실시간 운영’ 같은 배지를 임의로 붙이지 않는다.

### G. 회사·문의

회사소개서 국·영문 다운로드, 대표 인증/면허의 자리, 연락처. 목업용 빈 인증 슬롯은 `[인증 자료 목업]`으로 표시하며 가짜 인장을 그리지 않는다. 문의는 기술협력/사업상담 등 용도를 고르되, 이 단계에서 실제 전송하지 않고 ‘목업: 전송되지 않습니다’를 보인다.

## 5. 하위 화면의 형태

| 화면 | 배치와 상호작용 |
|---|---|
| 사업·기술 허브 | 상단 소개 + 업무/기술 보기 전환 + 21개 명칭의 텍스트 탐색. 대표3개 상세만 실제 구성, 나머지는 동일 틀의 목업 상세 |
| 기술 상세 | breadcrumb → 제목/문제/대표결과5:7 → 개요·방법·결과·관련자료 목차 → 이미지와 설명의 번갈아 배치 → 관련 실적/첨부 → 문의. 모바일은 한열 |
| 연구·성과 목록 | 검색 + 보드탭 + 기술/연도필터 → 줄단위 목록. 데스크톱 필터는 좌측, 모바일은 필터 버튼+바텀시트. 빈 결과·초기화·뒤로가기 상태 설계 |
| 게시글 상세 | 제목·분류·일자 → 본문/미디어 → 첨부 → 관련기술 → 이전/다음/목록. 본문없는 실적은 실제 메타만, 설명을 임의 작성하지 않음 |
| 플랫폼 상세 | 실제 화면/목업 화면 → 어떤 입력/행동/결과인지3단계 → 6~8초 기능영상 자리 → 적용기술. 개발중은 실제 상태를 그대로 유지 |
| 장비 | 업무필터 + 이미지·모델·용도 목록 → 대표3개 상세. 공개80항목은 원본으로 보관만 하고 전체 로딩하지 않음 |
| 회사 | 개요 → 연혁의 형태 → 조직/거점 → 자격/자료. 확실한 회사명·연락처·브로슈어는 실제값, 나머지 빈 슬롯은 목업 |
| 소식·문의 | 보드 틀3종과 문의 상태. 제출·외부메일 전송·구독 신청은 구현범위 밖 |

원래 기술ID·게시글ID를 보존해 나중에 실제 자료를 꽂을 수 있게 한다. 현재 모든 상세를 완전 작성하는 것은 범위 밖이다.

## 6. 국·영문

메뉴·제목·설명·버튼·필터·빈상태·목업표시·페이지 메타는 모두 한영 키를 갖는다. 언어 변경 시 같은 화면·항목·필터에 남는다. 대표 샘플의 영어를 먼저 검토하고, 나머지 전체 게시글 번역은 뒤로 미룬다. 원문 자료는 원문 언어로 안내한다. ‘V2 translation’, ‘needs-review’ 같은 내부 관리 문구는 방문자에게 보이지 않는다.

## 7. 시각 검수 기준

- 1440×900과390×844에서 회사 역할·주요CTA·현재 메뉴를 바로 식별할 수 있다.
- 국문 긴 기술명과 영문 메뉴가 잘리거나 겹치지 않는다.
- 대표 기술은 작은 캡처 묶음 대신 결과가 읽힐 크기로 보인다.
- 글·범례·영상조작이 서로 겹치지 않는다. 동영상이 없어도 화면 형태가 완성된다.
- 모든 목업 행·이미지·전송 동작을 실제 운영자료와 구분한다.
- Tab·Escape·터치·reduced-motion으로 같은 정보를 탐색한다.

이 문서는 메인 에이전트가 직접 결정한 화면 설계다. 서브에이전트의 앞선 화면 초안은 제작 지시로 사용하지 않는다.
