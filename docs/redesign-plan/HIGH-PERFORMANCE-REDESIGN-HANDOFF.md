## 작업의 출발점

현재 목업을 조금씩 고쳐 쓰지 않는다
홈페이지 디자인부터 다시 시작한다

현재 구현은 다음 자료를 확인하기 위한 참고본으로만 둔다

- 실제 GeoSR 장비와 조사 자료의 보존 위치
- 실제 AX 플랫폼 화면 녹화와 캡처
- 기존 홈페이지에서 가져온 연구와 인증과 지식재산권 자료
- 한글과 영문 페이지 구조
- 영상 제작 슬롯과 모션 구현 가능성

새 시안은 첫 화면의 인상과 정보 구조와 장면 리듬을 새로 정한다
목표는 한국의 해양·환경 엔지니어링 회사가 가진 현장성에 국제 기술 기업 수준의 밀도와 완성도를 더하는 것이다

## 사용자 검토에서 확정된 기준

- 자연 경관 회사처럼 보이면 안 된다
  - 현장 측량
  - 해양 관측
  - 조사선과 무인선
  - 항만과 해수욕장과 연안과 하천
  - 드론과 LiDAR와 지형 촬영
  - 부이와 수중 센서와 ROV
  - 실험 분석 장비
  - 수치모델과 공간정보
  - 위성 원격탐사와 AI 해석
  - AX 제품 경험
  이 한 회사의 연결된 역량으로 읽혀야 한다
- 첫 화면은 최종적으로 전체 화면 영상이다
- 디자인 가안에는 무작정 파란 네온선과 격자를 반복하지 않는다
- 생성 이미지에는 사람을 넣지 않는다
- 장비를 연출할 때는 실제 GeoSR 홈페이지에 있는 장비 원본을 기준으로 이미지 생성에 첨부한다
- 생성 이미지와 향후 영상은 한국의 해안과 항만과 하천과 육상 환경을 사실적으로 다룬다
- 실제 결과가 아닌 콘셉트에는 실제 수온과 염분과 클로로필 또는 위험 예측 결과처럼 보이는 수치와 범례를 넣지 않는다
- AX Platform과 GeoDAP은 독립된 서비스다
  - AX는 이 홈페이지 안에서 소개한다
  - GeoDAP은 외부 진입으로 연결한다
- 플랫폼 대표 화면은 전체 16:9 화면 또는 기능이 잘 드러나는 동일 비율 확대 화면으로 쓴다
  - 좌우가 비는 화면
  - 메뉴 일부만 보이는 화면
  - 브라우저 전체를 대충 축소한 화면
  을 쓰지 않는다
- 플랫폼의 실제 기능은 짧은 녹화와 GIF와 MP4로 보여준다
- 한글과 영문은 실제 기업 문장처럼 자연스럽게 다시 쓴다
- 화살표는 외부 이동과 개별 자료 열기처럼 목적이 분명한 경우만 쓴다
- 인증과 면허와 지식재산권은 분류별로 읽히게 한다

## 현재 시안에서 버릴 방향

- 큰 제목만 있고 영상 대기 상태가 넓게 비어 보이는 메인
- 자연 풍경만으로 기술력이 약해지는 구성
- 이미지 한 장이 교체되는 수준의 단순 슬라이드
- 파란 네온 선과 가상 격자를 반복하는 해양 AI 이미지
- 긴 가로 레일과 큰 여백으로 자료가 작아 보이는 인증 영역
- 일반적인 한국 엔지니어링 회사 홈페이지의 배너와 메뉴 중심 구성
- 첫 화면과 AX 화면과 GeoDAP 진입이 한 덩어리로 섞이는 구성

# 1. 메인 기업 영상

## 역할

메인 영상은 GeoSR이 무엇을 하는지를 지구 관측에서 실제 현장과 수중 관측까지 이어지는 한 번의 기술 여정으로 보여준다
자연을 감상시키는 영상도 아니고 AX 제품 데모도 아니다

핵심 문장은 현장과 관측과 분석을 연결해 환경 변화를 해석하는 회사라는 사실이다

| 54–60초 | 수중 센서 장면에서 지구의 푸른 가장자리로 다시 올라간다 | 수집된 관측이 위성·모델·분석의 큰 흐름으로 회귀한다 | 첫 프레임과 색온도와 카메라 방향을 맞춰 무한 루프를 만든다 |

## 제작 순서

1. 각 구간의 첫 프레임과 마지막 프레임을 이미지로 먼저 만든다
2. GeoSR 실제 장비와 한국 지리와 물리적 연결을 검수한다
3. Flow로 저해상도 움직임 초안을 만든다
4. 검수한 장면만 Higgsfield 고해상도 제작으로 넘어간다
5. 시작과 중간과 끝 프레임뿐 아니라 전체 프레임에서 장비와 지형 변형을 검수한다
6. 첫 프레임을 홈페이지 히어로의 영상 전 포스터로 사용한다

# 2. AX Platform 영상

## 메인 기업 영상과의 차이

메인 기업 영상은 현장에서 수집된 데이터가 어디서 오는지를 보여준다
AX 영상은 그 데이터와 분석이 사용자가 판단하고 실행할 수 있는 제품 경험으로 바뀌는 순간을 보여준다

AX 영상에 조사선과 수중 장비를 다시 길게 보여주지 않는다
현장 장면은 AX가 다루는 문제의 맥락으로 짧게만 사용한다
중심은 탐지와 예측과 모니터링이 실제로 어떻게 이어지는지다

## AX 상단 콘셉트 영상 30초

| 구간 | 장면 | 표현 원칙 |
| --- | --- | --- |
| 00–05초 | 실제 한국 해안 또는 항만의 중성적인 공간 장면 위에 관측과 분석 대상이 겹친다 | 결과값과 경보 등급을 꾸며내지 않는다 |
| 05–12초 | 탐지 단계 | 위성·공간정보·관측 데이터가 하나의 판단 장면으로 모이되 실제 AX UI를 가짜로 다시 그리지 않는다 |
| 12–20초 | 예측 단계 | 지형과 시간 조건과 모델 경로가 깊이감 있는 공간 전환으로 이어진다 |
| 20–27초 | 모니터링 단계 | 관측 지점과 변화 흐름이 연결되고 사용자가 판단할 다음 행동이 남는다 |
| 27–30초 | 세 장면이 AX Platform의 실제 제품 화면으로 접히며 다음 구역으로 이어진다 | 아래 실제 기능 녹화로 자연스럽게 넘긴다 |

AX 상단 영상은 제품의 기능적 약속을 보여주는 시네마틱 콘셉트다
가짜 대시보드와 읽을 수 있는 허구 데이터와 허구 제품 로고를 만들지 않는다

## 아래 플랫폼별 실제 기능 기록

AX 상단 콘셉트 영상 아래에는 각 플랫폼별 실제 화면 기록을 둔다

- 플랫폼은 대분류와 사용 목적을 먼저 읽히게 한다
- 각 플랫폼 카드는 동일한 16:9 프레임을 유지한다
- 각 프레임은 실제 플랫폼에서 녹화한 3초 내외의 MP4 또는 GIF를 재생한다
- 필요한 경우 전체 UI에서 실제 기능이 작동하는 구역만 같은 16:9 비율로 확대한다
- 탐지와 예측과 모니터링이 어떤 플랫폼의 어떤 기능인지 실제 화면과 함께 짧게 설명한다
- 정지 캡처는 영상 로딩 실패 시에만 쓰고 제품을 가짜로 재구성하지 않는다
- 자막과 라벨은 웹 텍스트로 두고 영상 안에 새로 만든 읽을 수 있는 UI 텍스트를 넣지 않는다

# 3. 홈페이지 디자인 작업 순서

## 1단계 디자인 보드

코드를 먼저 고치지 않는다
데스크톱 16:9 기준으로 서로 다른 세 가지 전체 디자인 방향을 만든다

각 방향은 다음을 하나의 흐름으로 제시한다

1. 영상 히어로
2. 장비와 조사 현장의 기술 증거
3. 관측과 분석과 예측의 연구 방식
4. AX Platform 콘셉트와 실제 기능 기록
5. GeoDAP의 독립된 Earth Data Intelligence 진입
6. 인증과 면허와 지식재산권
7. 대표 연구·사업·학술
8. 문의와 회사 정보

선정 기준은 최신 유행이 아니라 첫 화면에서 GeoSR의 실제 기술과 연구 역량이 읽히는가다

## 2단계 디자인 시스템

선택한 보드를 기준으로 다음을 확정한다

- GeoSR의 기존 푸른 계열과 검정과 어두운 남색을 중심으로 한 색 체계
- 임원진이 선호한 두꺼운 대형 타이포그래피의 쓰임과 한글 문장 리듬
- 영상과 실제 장비 사진과 제품 화면의 비율 체계
- 16:9 프레임과 세로 정보 패널과 분류형 자료 영역의 규칙
- 한글과 영문의 줄바꿈과 강조 규칙
- 링크와 외부 이동과 자료 열기 표식 규칙

## 3단계 인터랙션과 모션 설계

인터랙션을 최소한의 효과로 제한하지 않는다
다만 기술과 정보 구조를 설명하는 동작이어야 한다

- GSAP과 ScrollTrigger로 장면 전환과 스크롤 고정과 텍스트와 레이어의 시간차를 설계한다
- Lenis로 전체 이동의 관성과 밀도를 조정한다
- Three.js와 WebGL과 GLSL은 지구와 위성 관측과 공간 레이어와 수중 수층처럼 실제 개념이 있는 장면에서 사용한다
- CSS 3D와 마스킹과 오브젝트 확대와 필름 그레인과 깊이 이동을 함께 사용한다
- Lottie와 Motion One과 Anime.js는 장비 상태나 작은 제품 전환처럼 가벼운 모션에 사용한다
- 필요하면 Barba 기반 페이지 전환을 검토하되 다국어와 접근성 및 뒤로가기 동작을 먼저 검증한다
- 모든 장면은 정지와 재생과 마우스 반응과 스크롤 반응을 하나의 통일된 타임라인으로 설계한다
- 모바일과 `prefers-reduced-motion`에서는 핵심 정보가 남는 정적 또는 저모션 버전을 별도로 설계한다

# 4. 보존하고 조사할 자료 범위

현재 `dist/assets/`에 복사된 일부 장비만 다음 작업의 자료 범위로 제한하지 않는다

다음 세션은 기존 GeoSR 홈페이지와 저장소의 조사 자료와 미디어와 프로젝트 사례를 다시 인벤토리로 만든다

- 실제 장비 전체
  - 조사선
  - 무인선
  - 드론
  - 부이
  - 수중 ROV
  - 수중 센서
  - 측량 장비
  - 실험 분석 장비
- 조사와 연구 사례 전체
  - 해양과 연안
  - 항만과 해수욕장
  - 하천과 유역
  - 수질과 퇴적물과 생태
  - 재해와 침수와 폭풍해일
  - 위성영상과 원격탐사와 AI
  - 수치모델과 공간정보
- 기존 홈페이지의 실제 게시글과 보도와 연구와 학술과 특허와 인증과 면허
- 실제 AX 제품 화면과 기능 녹화 후보
- GeoDAP의 확정된 브랜드 화면과 외부 진입 규칙
- 기존 영상과 사진과 PDF와 설계 문서

전체 자료를 이번 목업 화면에 전부 이관한다는 뜻은 아니다
먼저 무엇이 있는지 정확히 파악하고 각 페이지와 장면에 가장 설득력 있는 근거만 고른다

# 5. 아스트라 작업 시작 체크리스트

- 기존 홈페이지와 저장소의 장비와 사례와 미디어 인벤토리를 만든다
- 실제 자료와 콘셉트 가안과 빈 슬롯을 명확히 구분한다
- 메인 기업 영상과 AX 영상의 스토리보드를 별도로 작성한다
- 메인 디자인 보드 세 방향을 만든다
- 한 방향을 선택한 뒤에만 페이지 코드를 전면 교체한다
- 이미지 생성 전 장면별 근거 자산과 프롬프트와 금지 요소를 검토한다
- 각 이미지와 영상의 한국 지리와 장비와 과학적 표현을 검수한다
- 실제 플랫폼 녹화를 16:9 클립으로 선별하고 각 기능에 연결한다
- 한글과 영문을 실제 기업 문장으로 동시 검수한다
- 데스크톱과 모바일과 저모션과 키보드 접근성을 마지막에 함께 검수한다
