# 목업 범위와 인수 기준

메인 설계 · 2026-09-17 · **지금은 틀을 만든다. 전체 자료를 이관하지 않는다.**

## 1. 원본과 목업을 분리

수집된1,105개 게시글, 21개 기술, 80개 장비와 첨부는 자료 원본으로 보존한다. 향후 본구축에 쓰기 위한 자산이다. 목업에서 전체JSON·이미지·PDF를 로드하거나 일괄번역하지 않는다.

목업은 작은 전용 fixture만 읽는 것으로 설계한다. fixture는 회사의 실제 자료와 임의의 예시를 구분하는 `kind: real-sample | placeholder`, 원본ID, locale, thumbnail, 첨부상태를 가진다. 실제 fixture 파일과 화면 코드는 구현 시작 후 만든다.

## 4. 목업 표시 규칙

- 모든 페이지 공통에 작은 ‘디자인 목업 / Design preview’ 표시. 지나치게 큰 경고띠로 디자인을 가리지 않는다.
- 실제자료 샘플은 ‘대표 자료’로 표시. 예시 글은 ‘목업 게시글 01’, 날짜는 ‘YYYY.MM.DD’, 기관은 ‘기관명 예시’.
- 빈미디어는 회색/옅은청색 면+비율+용도(예: ‘모델 결과 영상 · 목업’). 실제 측정값처럼 생긴 숫자 금지.
- 검색결과는 ‘샘플6건’처럼 실제 fixture수만 표시. ‘719건/1,105건’을 로드된 결과처럼 사용하지 않는다.
- 필터로0건이면 명확한 빈상태+초기화 버튼. 존재하지 않는 글로 페이지수를 부풀리지 않는다. 페이지네이션 디자인은 명시적예시 상태로만 보여준다.
- 문의·구독 제출은 네트워크 요청 없이 ‘목업입니다. 전송되지 않았습니다.’로 끝난다.
- KO/EN 전환은 목업표시에도 적용. 원문첨부 언어는 별도 표시한다.

## 5. 이번 구현에 포함 / 제외

포함: 공통헤더/메뉴/언어전환, 홈 레이아웃, 기술허브·대표상세, 게시판목록/상세/첨부상태, 대표플랫폼/장비, 회사·소식·문의 틀, 스크롤상태·영상제어·모바일·키보드.

제외: 전체 자료 이관, 게시판관리자/CMS, 로그인, 실제 문의메일전송, 전수번역, 전체첨부검수, 플랫폼 실시간데이터연결, 영상생성·공개배포. 기존자료를 삭제하라는 의미는 아니다.

## 6. 구현 순서

1. 작은 fixture와 공통레이아웃. 한국어/영어 키를 함께 정의.
2. 홈을 정지미디어로 배치한 뒤 기존영상1개를 연결한다.1440/390 모두 첫 화면 전체 자동재생·정지·대체포스터를 확인한다.
3. 기술상세·게시판목록·게시글상세의 서로 다른 템플릿 연결.
4. 나머지허브/회사/장비/플랫폼은 같은시스템으로 틀구성.
5. 모션을02문서 상태표대로 추가. 영상없어도 동작검증가능.
6. 대표자료와placeholder를 구분하고 문의전송·다운로드상태 확인.
7. 한영·키보드·모바일·실패상태 검수. 사용자에게 목업검토 요청.

그다음 단계에서 실제콘텐츠 확충·관계복원·영상제작을 별도로 계획한다. 21개 기술의 `s_addtext2`와 전체게시글 연결은 그때 처리한다. 이번에는 대표샘플의 관계만 테스트한다.

## 7. 목업 완료 기준

- 화면이01설계와 일치하고 실제 목업표시가 있다.
- 샘플12글/3기술상세/3장비/2플랫폼으로 핵심동작을 확인한다.
- KO/EN에서 같은 항목·필터·선택상태를 유지한다.
- 1440×900,390×844,최소320px에서 겹침·의도치않은가로넘침이 없다.
- 메뉴·검색·필터·상세·뒤로가기·Escape·포커스반환을 실제조작한다.
- 영상없음/이미지실패/0건검색/reduced-motion에서 내용과레이아웃이 유지된다.
- 전체수집JSON이나모든원본첨부가초기화면에딸려오지않는다.
- 성능 목표는LCP2.5초이하,CLS0.1이하,주요조작200ms이내. 로컬환경의모의측정과향후실서비스측정을구분하며 달성전완료수치로주장하지않는다.

지금 이 파일은 설계이며 **목업 구현은 아직 시작하지 않았다.** 기존프리뷰는 이전초안이다.
