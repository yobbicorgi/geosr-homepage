# GeoSR 회사 영상 장면 설계

2026-09-29 · 기획 확정안 · 유료 생성 전 입력 영상과 시작·끝 프레임 검수 필요

## 이 영상이 설명할 일

메인 영상은 장비를 나열하는 쇼릴이 아니다. **현실의 대상 → 관측·조사 → 분석 자료 → 관리·예측에 쓰이는 결과**가 하나의 흐름으로 읽혀야 한다. 우주·상공·수면·수중·자료 화면으로 관측 규모를 바꾸되 동일한 해안 풍경을 반복하지 않는다. 사용자의 최신 요청에 따라 약 4~5초인 서로 다른 주제 10개를 편집한다. 위성 주제만 관측과 분석을 각 4초로 나눠 총 8초다. 합격한 클립만 해당 기술 상세의 도입부에서 재사용한다. 상세 본문에는 GeoSR 원문 그림과 설명을 그대로 둔다.

한화오션은 사이트의 화면 배치와 동적 피사체·전폭 미디어 운영 방식에 대한 디자인 기준이다. 다른 영상은 **촬영·자료화·분석이 보이는 방식만** 조사했다. 영상·스틸·로고·소스 코드는 가져오지 않는다.

기술 사실 확인은 [ESA Sentinel-2 임무 설명](https://www.esa.int/Applications/Observing_the_Earth/Copernicus/Sentinel-2)과 [Fugro 수로측량 설명](https://www.fugro.com/expertise/hydrographic-surveys) 및 GeoSR [기술 원문 조사](../../company-audit/technology-analysis.md)에 근거한다. ESA와 Fugro의 장비 성능·수치는 GeoSR 보유 장비의 사양으로 전용하지 않는다. 화면 속 자료는 개념 표현이며 실제 관측 결과라고 표기하지 않는다.

## 메인 영상 편집 순서

완성 목표는 약 48초 · 주제 10개 · 실제 제작 클립 11개다. 컷마다 대상과 결과가 달라야 하므로 아직 합격하지 않은 클립 수에 맞춰 길이를 늘리지 않는다. 처음 2초 안에 풍경과 물체의 이동이 보여야 하고 소리 없이 이해되어야 한다. `Geo Data Intelligence` 문구는 사이트의 실제 텍스트로 유지한다. 영상 안에는 또 다른 큰 슬로건을 넣지 않는다.

## 위성 01 콘티 · 최우선 제작

**01A 0~4초 — 관측:** 시작 프레임은 지구 곡률과 한반도 주변의 광역 해역을 보이되 위성 크기는 화면의 작은 일부로 제한한다. 카메라는 위성과 같은 방향으로 전진한다. 위성이 지표에 불가능한 밝은 레이저를 쏘지 않는다. 촬영 띠가 위성 진행 방향을 따라 생기며 동일 지형의 광학 영상 타일로 전환될 준비를 한다.

**01B 4~8초 — 자료와 쓰임:** 획득 영상 타일이 화면을 차지하면서 동일한 하구·해안 윤곽을 유지한다. 원영상의 수역 일부에만 해색·수온 등 **하나의 선택한 환경 변수**를 설명하는 분석층이 채워진다. 작은 원영상 인셋이 잠깐 남아 입력과 결과의 관계가 보인다. 마지막에는 관심 수역이 분명하게 하이라이트된다. 인셋·분석층·주석은 영상 생성 과정에서 함께 만들고 사이트에서 사후 박스를 얹지 않는다. 숫자·좌표·지명·실제 관측 날짜는 넣지 않는다.

기술 56 원문에는 위성 및 초분광 자료와 해색 검보정 및 적조·녹조·냉수대·고수온 모니터링이 있다. 첫 영상은 그중 **연안 해색 변동의 영상처리**로 범위를 좁힌다. 개별 선박이나 어류를 이 장면에서 위성으로 탐지하지 않는다. 광학 영상의 공간 규모와 분석층 해상도가 서로 어긋나면 실패다.

제작 입력: 현재 검수된 위성 상세용 정지 이미지 · 원본은 별도 보관소의 `media-source/editorial/satellite-optical-native-20260929.png`는 01B 지형·색 기준이다. 같은 지형을 참조한 별도의 01A 궤도 시작 프레임과 01B 분석 종료 프레임을 ChatGPT 웹 대화에서 제작·검수한다. Seedance 2.0의 시작·끝 이미지 역할을 각각 사용한다. 한 번에 8초로 무리한 4단계 변환을 강요하지 않고 4초 클립 둘을 연결한다. 실제 비용은 두 입력과 모델 옵션을 확정한 뒤 다시 조회한다.

## 02 드론 측량 · 4초

[기술 64 원문](https://www.geosr.com/sub/business/conserve_view.asp?idx=64)은 무인항공 사진·LiDAR 측량으로 점군·정사영상·DEM을 만든다. 이 컷은 **사진측량에서 정사영상으로 이어지는 과정 하나**를 선택한다. LiDAR 점군까지 한 번에 섞지 않는다. 촬영 대상은 실제 규모의 넓은 해빈과 하구의 완만한 지형이다. 고정익 또는 회전익 중 하나의 기체만 선택하고 원문 사진의 기체 형태를 참고한다. 특정 장소의 실제 촬영 성과라고 주장하지 않는다.

0~1초에는 작은 드론이 화면 상단의 해안을 따라 이동하고 전경의 모래·식생·수면이 시차를 보인다. 1~3초에는 카메라가 드론을 따라 부드럽게 전진하면서 연속 촬영의 범위가 **뒤쪽 지표에만** 짧게 남는다. 3~4초에는 같은 해안선과 사구의 실제 위치를 유지한 채 지나온 구간이 위에서 본 정사영상 질감으로 정합된다. 정사영상은 화면 속 자료 변화로 생성하며 별도 사이트 박스를 올리지 않는다. 거대한 드론·유인 항공기 형상·공중에 뜬 격자·촬영하지 않은 영역의 지형 변화는 불합격이다.

## 03 연안 감시 · 4초

[기술 58 원문](https://www.geosr.com/sub/business/conserve_view.asp?idx=58)은 고정 CCTV 자료의 영상 처리와 연안 변화 분석을 설명한다. 기술 53의 해안침식 조사 및 장기 해빈 기록과 연결하되 CCTV 한 컷이 곧바로 수십 년 변화나 재해 예측 전체를 증명한다고 표현하지 않는다.

0~1초에는 **고정된 카메라 시점**에서 한 해변의 파도와 해안선이 움직인다. 1~3초에는 같은 카메라와 지형을 유지하며 실제 젖은 모래·마른 모래 경계에 맞는 가는 판독 선이 나타난다. 3~4초에는 같은 구도의 다른 시기 정지 화면이 잠깐 겹쳐져 경계 위치의 차이가 읽힌다. 다른 시점의 해안 지형을 자연스럽게 순간 변형하는 영상은 쓰지 않는다. 사람 얼굴이 드러나지 않고 카메라 설치 위치와 촬영 방향이 타당해야 한다. 임의 날짜·침식률·가짜 경보 UI는 넣지 않는다.

## 생성과 합격 기준

### 연속 이미지 활용

각 주제는 대상이 보이는 전경·작동 중간·분석 결과의 2~3장으로 준비한다. 장소와 장비가 같은 연결 컷은 기존 이미지를 편집해 지형과 형상을 유지한다. 다른 각도는 실제 카메라 이동으로 연결 가능한 범위인지 확인한다. 영상의 시작·끝 프레임과 참고 이미지로 사용하거나 영상이 없는 웹 영역에서 스크롤에 따른 장면 전환으로 활용한다. 슬라이드에는 실제로 서로 다른 단계가 보이는 이미지를 사용하고 같은 사진의 확대본만 반복하지 않는다. 2~3장은 제작 기준이며 장면에 필요한 만큼만 추가한다.

1. 소스 기술 원문과 기존 회사 자료에서 대상·장비·자료 처리·결과를 먼저 고른다. 이미 확정된 상세 원문 그림은 유지한다.
2. ChatGPT 웹에서 같은 구도와 지형의 **시작·끝 고해상도 이미지**를 만든다. 시작 화면에 이미 분석 완료 상태가 가득하면 해당 장면은 영상 입력으로 사용하지 않는다.
3. 시작과 끝의 지형·해안선·장비 형상·피사체 수·카메라 방향을 대조한다. 중간에 바뀌면 유료 작업을 접수하지 않는다.
4. Seedance 2.0 `std` · 1080p · 16:9 · 무음으로 한 장면씩 접수한다. 사용 크레딧과 원본·결과의 ID 및 프롬프트를 영수증에 남긴다.
5. 첫·중간·끝 프레임뿐 아니라 대상이 행동하는 연속 프레임을 확인한다. 정지 이미지의 확대·흔들림이나 분석장의 미세한 떨림만 있으면 제외한다.
6. 지형과 해안선의 연속성, 어류 자세와 박스·마스크 추적, 장비·케이블·선체 규모, 분석 결과의 공간적 정합을 본다. 불합격 영상은 사이트에 넣지 않고 같은 실패 입력으로 반복 결제하지 않는다.
7. 합격 클립만 컷과 기본 전환으로 연결해 메인에 배치한다. 동일 클립은 **같은 기술 상세**에서 재사용할 수 있다. 타사 참고 영상이나 이미지 픽셀을 복제하지 않는다.
